## Pedestrian geometry

Input is centre, observed planar velocity and physical full dimensions. Conservative physical rectangle (transformed source axes at the ROS boundary) remains included in every hull. An isotropic safety radius is at least the enclosing physical radius. Moving pedestrians add keypoints at heading +/-110 degrees and, only for nonzero force, along resultant force at Ds+alpha*|F|. Stationary pedestrians use symmetric conservative physical safety geometry. Hull construction is deterministic, finite and bounded.

Driving force is initially zero because desired velocity equals observed velocity. Force uses a bounded exponential repulsion away from the nearest whole blocked-cell boundary or finite-domain boundary in the exact selected grid, plus repulsion away from LFPC human/cane centre, amplified if that centre is within +/-110 degrees of heading. Nearest-boundary selection avoids raster-density-dependent accumulation. Repulsion is acceleration-like m/s^2; alpha has s^2 units converting its magnitude to metres, not a prediction duration. Gains, decay length, radius, maximum force/extension, data age and input caps are explicit validated parameters. No attraction, noise, inter-person interactions or intended-goal estimate. Nearest boundary cost is bounded by existing finite grid and cooperative deadline; no second classifier.

## One inflation pipeline

`ConvexCorridor::buildStatic` accepts optional dynamic convex polygons, empty by default. Share the existing separator via a container template so the four-corner static path retains operation order. Candidate directions remain ellipsoid stationary directions, support switches, and endpoint-clearance-active directions for every complete polygon. Dynamic polygons get local coordinates, common-plane exclusion and final independent certificates. Protected segments are checked for dynamic obstruction before inflation to distinguish DYNAMIC_REFERENCE_BLOCKED from numeric failure. Partial regions are cleared on any failure. Existing region/elapsed caps and static crop/horizon remain.

## ROS boundary and recovery

One source-enable parameter derives from existing `use_pedestrians`; false ignores dynamic data only for planner 3. Enabled source stores receipt/header state separately from the legacy obstacle flow. Reject count/array mismatch, nonfinite or unsupported geometry/velocity, zero/future/stale timestamps, invalid frame and unavailable transform. TF at observation time transforms centres and vectors and conservatively encloses transformed full body corners; arbitrary map/world identity is never assumed. Every build checks freshness again. A fresh empty frame is valid and clears pedestrian markers. Invalid data replaces prior valid state rather than retaining stale geometry. A later valid clear frame rebuilds the unchanged reference without automatic A* rerouting.

The crossing starvation bugfix uses the current dirty primary's already-integrated P2 files as baseline (per-file SHA manifest), not a new full patch against 96bc339. Its transaction holds the observation mutex continuously across snapshot binding, geometry, MPPI and authorized integration/output; new callbacks queue until commit. Callback entry receipt is preserved before waiting, and the immutable original header/receipt ages are checked before LFPC advance. This deliberately replaces strict rejection of all during-MPPI arrivals, which caused 10 Hz starvation. Accepted blockers still STOP; pending/unprocessed blockers are not claimed checked by the preceding commit. No age-threshold change, retry or FIRI/MPPI-cost change. Locked helper ownership avoids recursion and retains goal-reset exclusion; unlock precedes visualization sleep. See the current-frame contract for queue/latency limits.

## Diagnostics and evidence

Append enum reasons DYNAMIC_DATA_INVALID and DYNAMIC_REFERENCE_BLOCKED; retain old metric positions. Body and social hull outlines use stable namespaces on the existing corridor MarkerArray, transient lifetime and DELETEALL each publication. Static failure snapshots remain exact; any call with dynamic polygon inputs suppresses static-only capture and emits explicit DYNAMIC_INPUT_NOT_CAPTURED. This deliberately limits exact dynamic failure replay to test fixtures, rather than misrepresenting incomplete captures. A future versioned snapshot extension can remove this limitation.

`Result::has_dynamic_input` also blocks static-only capture at the capture API itself without consuming its static latch. First version accepts at most one pedestrian (more means explicit invalid data). A circumscribed octagonal safety disk is included alongside the full physical rectangle, so stationary geometry is symmetric and moving geometry retains full physical extent. Exact parameter ranges and launch/metric contracts are recorded in `current-frame-pedestrian-corridor.md`. Freshness is checked again after MPPI before integration. Source values are retained with the original header; transformed planar observation values are separate. Gazebo truth takes precedence over lightweight source if both flags are set, and world-pedestrian enable without a valid source fails closed.
